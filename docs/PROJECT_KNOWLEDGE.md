# 다음 시즌 유럽 5대 리그 득점 예측: 프로젝트 지식 정리

## 1. 한 문장 정의

현재 시즌 유럽 5대 리그에서 900분 이상 출전한 FW/MF를 대상으로, 다음 시즌 유럽 5대 리그에서 기록할 득점 수를 시즌 시작 전에 예측하는 프로젝트다.

이 프로젝트가 예측하는 것은 선수의 전 세계 모든 대회 득점이 아니다. 다음 시즌에 유럽 5대 리그 기록이 없으면 `next_goals=0`으로 정의한다.

## 2. 문제를 두 단계로 나눈 이유

전체 선수의 다음 시즌 득점에는 성격이 다른 두 사건이 섞여 있다.

1. 다음 시즌에도 유럽 5대 리그 기록이 존재하는가?
2. 기록이 존재한다면 몇 골을 넣는가?

이를 다음과 같이 분리했다.

- Model A: `P(다음 시즌 Big5 기록 존재)`
- Model B: `E(다음 시즌 득점 | Big5 기록 존재)`
- Hard Two-stage: Model A의 확률이 임계값보다 낮으면 0골, 그렇지 않으면 Model B 예측값 사용
- Soft Two-stage: Model A의 확률과 Model B 예측값을 곱해 기대 득점 계산

개발 구간과 최종 테스트 모두에서 Hard Two-stage가 전체 MAE 기준 가장 좋았다. 따라서 이 데이터와 평가 프로토콜에서 MAE를 우선할 경우 ‘리그 잔류 여부’와 ‘잔류 후 득점력’을 분리하는 접근이 지지된다. 모든 지표에서 Two-stage가 우월하다는 뜻은 아니다.

## 3. 데이터와 타깃

### 데이터셋

| 데이터셋 | 학습 구간 | 행 수 | 용도 |
|---|---:|---:|---|
| `long_basic` | 2000-01→2001-02 ~ 2022-23→2023-24 | 22,430 | 장기간 공통 기본 피처 실험 |
| `recent_advanced` | 2017-18→2018-19 ~ 2022-23→2023-24 | 5,666 | xG/xAG·슈팅·전진 지표 비교용으로 구축했으나 최종 파이프라인에는 미사용 |
| Validation | 2023-24→2024-25 | 923 | 개발 단계 평가 |
| Final Test | 2024-25→2025-26 | 926 | 구조를 동결한 뒤 v3에서 최종 지표를 산출한 평가 |

### 실제 최종 데이터 계보

최종 05~11 모델링 파이프라인은 `recent_advanced`가 아니라 `long_basic`에서 출발한다.

```text
long_basic
→ 최근 3시즌 득점 이력
→ 이전 소속팀 성적
→ leakage-safe Transfermarkt 시장가치·이적·새 팀 환경
→ Model A + Model B
→ Hard Two-stage
```

최종 모델은 xG, xAG, 슈팅, 전진 지표 등 `recent_advanced` 전용 피처를 사용하지 않는다. 따라서 `recent_advanced`는 구축된 비교 가능 데이터셋이지 현재 최종 모델의 메인 입력이 아니다.

### 타깃과 감사 컬럼

- `next_goals`: 다음 시즌 유럽 5대 리그 득점
- `next_10plus`: 다음 시즌 10골 이상 여부
- `matched_next`: 다음 시즌 기록 매칭 여부를 나타내는 감사용 컬럼이자 Model A의 정답
- `matched_next`는 Model A의 입력이 아니라 타깃으로만 사용한다. 회귀 모델을 포함한 입력 피처로 사용하면 누수가 발생한다.

### 데이터에서 확인한 기본 특성

- 현재 시즌 `goals`와 `next_goals`의 상관계수는 약 0.65로 가장 강했다.
- FW의 다음 시즌 평균 득점은 약 4.99골, MF는 약 1.44골이었다.
- 리그별 평균 차이는 포지션 차이보다 작았다.
- 통계적 극단값에는 실제 고성과 선수가 포함되므로 IQR 기준으로 일괄 제거하지 않았다.
- 비정상적으로 큰 `starts`나 `minutes`는 선수 성과가 아니라 원본 집계 문제일 가능성이 있어 별도 감사 대상으로 남겼다.

## 4. 평가 원칙

축구 시즌 데이터는 시간 순서가 있으므로 랜덤 분할보다 Walk-forward 평가가 적합하다.

이 프로젝트에서 채택한 원칙은 다음과 같다.

- 과거 시즌으로 학습하고 바로 다음 시즌을 평가한다.
- 평균 성능만 보지 않고 Fold 표준편차와 최악 Fold를 함께 본다.
- MAE를 주 지표로 사용하되 RMSE, R², bias도 함께 기록한다.
- 10+, 15+, 20+ 득점자의 MAE와 bias를 별도 확인한다.
- 이적 선수, 리그, 포지션, 실제 이탈 선수 등의 slice를 별도 평가한다.
- 최종 테스트의 feature, 모델 구조, threshold는 정답 공개 전에 확정한다.

단일 Validation 점수만으로 모델을 고르면 특정 시즌에 과적합된 결정을 할 수 있다. 이 프로젝트의 중요한 성과 중 하나는 모델 자체뿐 아니라 시간 누수를 막는 평가 절차를 확립한 것이다.

## 5. 모델링 과정에서 얻은 결과

### 5.1 기본 모델 비교

| 모델 | Walk-forward MAE | 해석 |
|---|---:|---|
| CatBoost | 2.389 | 기본 비교 1위 |
| XGBoost | 2.423 | CatBoost보다 소폭 열세 |
| Baseline MLP | 2.428 | 딥러닝 우위 없음 |
| ElasticNet | 2.429 | 단순 모델도 경쟁력 있음 |
| RandomForest | 2.435 | CatBoost보다 열세 |
| 현재 득점 그대로 사용 | 2.780 | 모든 학습 모델보다 나쁨 |

CatBoost가 근소하게 가장 좋았지만 모델 간 차이는 크지 않았다. 복잡한 모델이 자동으로 큰 개선을 주는 문제는 아니었다.

### 5.2 HPO의 교훈

- Tuned MLP MAE: 2.392
- Tuned CatBoost MAE: 2.398
- 고정 CatBoost baseline MAE: 2.389

튜닝된 CatBoost는 baseline보다 좋아지지 않았다. 선택 외부 피처를 고정한 뒤 다시 수행한 HPO에서도 Tuned CatBoost MAE는 2.399였고, 고정 S3 CatBoost의 2.383보다 나빴다.

따라서 이 프로젝트에서 HPO는 성능 개선을 보장하지 않았다. Inner-fold에서 선택한 설정이 Outer-fold 개선으로 이어지지 않아 일반화 실패 또는 선택 과적합 가능성이 나타났다. 튜닝 전 고정 baseline을 반드시 유지해야 한다.

### 5.3 외부 피처

선택된 외부 피처 조합 S3는 시장가치, 이적 상태, 새 팀 환경을 활용하되 이적료·경제성 피처는 제외한다.

- S0 기본 피처 MAE: 2.399
- S3 선택 외부 피처 MAE: 2.383
- S4 경제성 포함 MAE: 2.385

경제성 피처를 더 넣는 것이 성능을 높이지 않았다. 반면 Transfer context 전체를 제거하면 최종 선택 구조의 개발 MAE가 2.127에서 2.211로 약 0.085 나빠졌다. 시장가치 피처 제거의 악화 폭은 약 0.015였다.

핵심 교훈은 ‘외부 데이터가 많을수록 좋다’가 아니라, 예측 시점에 알 수 있고 선수의 다음 환경 변화를 직접 표현하는 피처가 중요하다는 것이다.

### 5.4 라벨 감사

`matched_next=False` 전체를 오류로 간주하지 않고, 명백한 모순만 보수적으로 수정했다.

- 개발 행 수: 7,572
- 수정한 라벨: 20건
- 복원된 득점 합계: 95골
- 복원된 10골 이상 사례: 3건

감사 후 Model A의 ROC-AUC는 0.912에서 0.924로, Macro F1은 0.820에서 0.833으로 좋아졌다. 반면 Model B MAE는 2.388에서 2.397로 소폭 나빠졌다.

이는 데이터 정제가 반드시 평가 점수를 높이지는 않는다는 좋은 사례다. 어려운 사례가 잘못 제외되어 있었다면 라벨을 바로잡은 뒤 모델 점수가 나빠지는 것이 오히려 정직한 결과다.

### 5.5 Two-stage 통합

| 방법 | 개발 MAE | 개발 RMSE | 개발 R² |
|---|---:|---:|---:|
| Hard Two-stage | 2.127 | 3.259 | 0.474 |
| Soft Two-stage | 2.168 | 3.243 | 0.479 |
| Direct Regression | 2.202 | 3.280 | 0.468 |
| Conditional Model without gate | 2.385 | 3.394 | 0.430 |
| 현재 득점 그대로 사용 | 2.752 | 4.038 | 0.192 |

Hard gate는 전체 MAE가 가장 좋았고 Soft gate는 RMSE와 R²가 근소하게 더 좋았다. 따라서 최종 선택은 ‘모든 오차를 동일하게 보는 평균 절대오차’를 우선한 결정이다.

## 6. 최종 테스트 결과

2024-25 시즌 정보로 2025-26 시즌을 예측한 926명의 locked holdout 결과다.

개발 데이터에는 09-01A의 보수적 audited label을 사용했지만 Final Test에는 원본 locked `test.csv` 라벨을 사용했고 사후 보정은 적용하지 않았다. 따라서 아래 수치는 **원본 locked test 라벨 기준 성능**이며, 원본 라벨에 남아 있을 수 있는 매칭 오류의 영향도 포함할 수 있다.

| 방법 | MAE | RMSE | R² | Bias |
|---|---:|---:|---:|---:|
| Final Hard Two-stage | **2.003** | 3.099 | 0.406 | +0.327 |
| Direct Regression | 2.067 | **3.084** | **0.412** | +0.312 |
| Conditional Model without gate | 2.259 | 3.213 | 0.361 | +0.683 |
| 현재 득점 그대로 사용 | 2.756 | 4.120 | -0.050 | +1.298 |

Hard Two-stage는 MAE가 가장 좋았다. Direct Regression은 RMSE와 R²가 근소하게 좋았다. 따라서 최종 모델의 우위는 절대적이라기보다 선택한 목적함수에 따른 우위로 해석해야 한다.

최종 실행본은 `11_final_test_slice_error_analysis_v3.ipynb`다. v1과 v2는 파이프라인 준비 및 오류 수정 단계이며, v2에서 datetime 해상도 정규화와 cutoff 누수 검사를 강화했고 v3에서 정렬 이후 stale boolean mask 위험을 수정했다. 최종 지표는 행 정합성 수정이 반영된 v3에서 산출됐다.

Model A의 최종 테스트 성능은 다음과 같다.

- 임계값: 0.67
- ROC-AUC: 0.907
- Macro F1: 0.814
- Exit recall: 0.680
- Presence recall: 0.936

## 7. 어디에서 잘하고 어디에서 실패하는가

### 포지션과 리그

- FW MAE: 2.653
- MF MAE: 1.269
- Premier League MAE: 2.450
- Serie A MAE: 1.783
- Bundesliga MAE: 1.835

전체 평균만 보면 FW에서 발생하는 큰 오차가 가려진다. 평균 득점이 낮은 MF는 비교적 쉬운 반면, 득점 분산이 큰 FW는 별도 모델 또는 목적함수가 필요할 수 있다.

### 이탈과 팀 변경

- 실제 Big5 이탈 선수 MAE: 0.905
- 실제 Big5 잔류 선수 MAE: 2.259
- 프리시즌 팀 변경 선수 MAE: 1.740, bias +0.906

Hard gate는 이탈 선수의 0골 처리를 잘해 전체 MAE를 크게 줄였다. 반면 잔류 선수의 득점량 예측은 여전히 더 어려운 문제다.

### 고득점자 과소예측

| 실제 득점 구간 | 선수 수 | MAE | Bias |
|---|---:|---:|---:|
| 10+ | 67 | 5.660 | -5.295 |
| 15+ | 22 | 7.172 | -6.995 |
| 20+ | 5 | 10.426 | -9.954 |

이것이 프로젝트의 가장 중요한 실패 패턴이다. 전체 MAE를 최소화하는 회귀 모델은 소수의 고득점자보다 다수의 저득점자에 맞추는 것이 유리하므로 평균으로 수축한다.

따라서 ‘전체 선수의 기대 득점 예측’과 ‘다음 시즌 고득점자 발굴’은 같은 모델로 완전히 해결되지 않을 수 있다. 후자를 중요하게 본다면 10+ 분류, 순위 학습, quantile loss, 가중 손실 등을 별도 실험으로 다뤄야 한다.

## 8. 이 프로젝트에서 일반화할 수 있는 지식

1. 시간 데이터는 랜덤 분할보다 Walk-forward 검증이 우선이다.
2. Validation 한 시즌의 1등보다 여러 Fold의 평균·분산·최악 성능이 중요하다.
3. HPO는 baseline을 이겨야만 채택한다. 튜닝 자체는 성과가 아니다.
4. 누수 방지는 피처뿐 아니라 라벨, 외부 데이터의 기준일, 최종 테스트 공개 시점까지 포함한다.
5. 데이터 감사 후 점수가 나빠져도 데이터가 더 정확해졌다면 올바른 진전일 수 있다.
6. 전체 MAE가 좋아도 중요한 소수 집단에서 심각하게 실패할 수 있으므로 slice 평가가 필요하다.
7. 문제를 구성하는 서로 다른 사건을 분리하면 단일 회귀보다 설명 가능하고 강한 구조를 만들 수 있다.
8. 더 많은 피처보다 예측 시점에 실제로 알 수 있는 안정적인 피처가 중요하다.

## 9. 현재 결론과 다음 연구 질문

현재 프로젝트의 최종 모델은 Full feature set을 사용하는 Hard Two-stage다. 최종 테스트 MAE는 약 2.00골이다.

다음 단계는 최종 테스트에 맞춰 모델을 다시 선택하는 것이 아니라, 이미 드러난 실패 원인을 새로운 개발 프로토콜에서 연구하는 것이다.

- FW와 고득점자 전용 목적함수가 필요한가?
- 득점 수를 count distribution으로 모델링하면 평균 수축을 줄일 수 있는가?
- 10+ 분류와 득점 회귀를 multi-task로 결합하면 순위 품질이 좋아지는가?
- 확률 보정과 gate 임계값이 다른 시즌에도 안정적인가?
- 데이터 생성부터 최종 예측까지 재현 가능한 pipeline으로 분리할 수 있는가?

Final Test 결과는 위 질문의 모델 선택 데이터로 재사용하지 않는다. 새로운 개선안은 별도의 미래 시즌이나 다시 정의한 개발 구간에서 평가해야 한다.
